## 2. 이 순위를 그대로 믿으면 안 된다 — 부트스트랩 2,000회

| 전략 | n | PF 95% 신뢰구간 | P(PF < 1) | 거래당 손익 95% CI |

| A Pullback | 81 | **[0.98, 2.51]** | 3.0% | [−14,064 , +745,453] |
| B CHoCH | 41 | **[0.47, 2.04]** | **44.5%** | [−460,331 , +592,482] |

읽는 법:

- **B(CHoCH)는 손익분기와 구분되지 않는다.** PF<1 확률이 44.5% 다.
  "CHoCH 가 더 낫다" 는 이 데이터로 지지되지 않는다.
- **A 는 하한이 0.98 로 1.0 에 걸쳐 있다.** 양(+)이라고 단정하기 어렵다.
- **C 만 하한이 1.0 을 넘는다.** 단, C 는 재현 불가 게이트를 뺀
  **상한 추정치**라 운영 성과가 아니다 (STRATEGY_BASELINE §2).

**세 전략의 신뢰구간이 서로 크게 겹친다. 1년·41~81거래로는
"어느 전략이 더 낫다" 를 결론 낼 수 없다.**

## 3. 기록된 근거와의 불일치 — 확인 필요

`swing_runner._entry_engine` 의 docstring 은 CHoCH 채택 근거를 이렇게 적고 있다.

```
근거 (Iteration 8, Top-3 상한 · 공통 청산):
    pullback  140거래 승률32.9% PF1.126  Train PF 0.966(손실)
    choch      59거래 승률40.7% PF1.639  세 구간 모두 1.3 이상
```

이번 baseline (같은 Top-3 상한 · 공통 청산):

```
    pullback   81거래 승률41.98% PF1.560
    choch      41거래 승률31.71% PF1.060
```

**승률과 PF 의 우열이 뒤집혔다.** 데이터셋·기간이 다르므로
어느 쪽이 틀렸다고 단정할 수 없다. 다만 **CHoCH 전환의 근거는
이 데이터셋에서 재현되지 않는다.** feature flag 기본값이
`pullback` 인 현 상태는 유지하는 것이 맞다.

원인 후보(미검증): 종목 유니버스 차이, 기간 차이, 리샘플 방식 차이.
→ 8-1 에서 같은 유니버스·기간으로 재현 확인이 필요하다.

## 4. 전략별 성격

| | A Pullback | B CHoCH | C Expl(core) |
|---|---|---|---|
| 신호 빈도 | 792 신호일 (많음) | 80 (적음) | 211 |
| 신호 종목 수 | 111/112 | 43/112 | 93/112 |
| 병목 | **슬롯 (646건 폐기)** | 신호 부족 | 슬롯 (130건 폐기) |
| 승률 | 41.98% | 31.71% | 43.08% |
| 손실 관리 | 평균 −2.11% | 평균 −2.78% | 평균 −1.62% |
| MDD | **−8.29% (최소)** | −14.98% (최대) | −11.65% |

- **A 는 신호가 남아돈다.** 슬롯 3개가 병목이라 792개 중 81개만 실행된다.
  선별 규칙(ScoreEngine 순위)이 성과를 좌우한다 → 8-1 의 지렛대.
- **B 는 신호 자체가 부족하다.** 112종목 중 43종목에서만 나오고 월 3.54건이다.
  통계적 판단에 필요한 표본이 안 모인다.
- **C 는 빈도·승률·PF 가 균형적이지만 Reference 다.** 게이트를 다 붙이면
  거래수가 줄어들고 성과도 달라진다 — 얼마나 달라질지는 **확인 불가**.

## 5. 실거래와의 대조

실거래(2026-05~07)는 EC_HALT 때문에 거래가 거의 없었고,
있었던 swing 5건이 손실의 95.2% 였다 (Iteration 4).
이번 백테스트의 A(PF 1.56)와 실거래 결과가 맞지 않는다.

이 차이는 이번 이터레이션의 범위 밖이며, 다음 중 어느 것인지 **확인 불가**:
유니버스 차이 / 진입 타이밍(일봉 종가 vs 장중) / 청산 프로파일 근사 /
실거래 표본 5건의 우연.
