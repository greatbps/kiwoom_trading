## 2. 오늘 스냅샷으로는 판별이 불가능하다

2026-08-03 은 미결제 잔액이 0 이다.

```
d1_sel_exct_amt = d1_buy_exct_amt = d2_sel_exct_amt = d2_buy_exct_amt = 0
당일 체결 0건
entr = pymn_alow_amt = ord_alow_amt = d1_entra = d2_entra = 1,857,799
```

**모든 후보가 같은 값이 나온다.** 오늘 데이터만으로 "A 가 최선" 이라고 말하면
그건 판별이 아니라 동률이다. 그래서 선정 근거를 아래 §3 으로 옮긴다.

동시에 이 결과가 확인해 주는 사실이 하나 있다:
**미결제가 없는 날에는 현재 계산식 A 가 브로커 값과 정확히 일치한다(오차 0원).**
현재 계산식은 상시 틀린 게 아니라 **결제 미완료 구간에서만** 틀린다.

## 3. 선정 근거 — 결제 사건 실측 (`D2_SETTLEMENT_ANALYSIS.md`)

현재 계산식 A 는 결제 구간에서 **양방향으로** 틀린다.

| 사건 | A 의 값 | 실제 | 오차 |
|---|---|---|---|
| 2026-05-22 매도 4,526,860 직후 | 542,250 | ≈5,060,540 | **-4.52M (과소)** |
| 2026-06-24 매수 2,121,000 미결제 | 6,628,719 | ≈4,543,409 | **+2.09M (과대)** |

- **B(`entr`)** 는 매도측은 고치지만 매수 미결제가 차감되지 않아
  2026-06-24 형 과대계상이 남는다. (운영 코드 주석의 2026-07-06 이중계산 이슈)
- **D(당일매도체결금 가산)** 도 매도측만 고친다. 게다가 결제일을 자체 추정해야 해
  T+N 이 바뀌면 조용히 틀린다.
- **E(`d1_entra`)** 는 결제 1일분만 반영해 T+2 구간을 못 덮는다.
- **C(`d2_entra`)** 는 매도·매수 정산을 모두 반영한 D+2 시점 예수금이다.
  두 방향 모두 한 필드로 해결되고, 결제일 계산을 코드가 하지 않는다.
- **F(`aset_evlt_amt`)** 는 브로커가 직접 준 총자산이라 가장 단순하지만,
  오늘 값이 `entr + tot_evlt_amt` 와 정확히 일치한다
  (1,857,799 + 1,827,000 = 3,684,799). 이 항등식이 `entr` 기반인지
  `d2_entra` 기반인지는 오늘 두 값이 같아서 **확인 불가**.
  `entr` 기반이면 F 는 B 와 같은 과대계상 결함을 물려받는다.

**→ 권고: Case C `d2_entra + 주식평가액`.**

## 4. 확정 전 필요한 측정 1회 (미실시)

오늘로는 아래를 구분할 수 없다. **미결제 잔액이 있는 날 kt00001/kt00004 를
1회 덤프하면 전부 결정된다.**

| 확인할 것 | 방법 |
|---|---|
| `d2_entra` 가 매도 미결제분을 포함하는가 | 매도 당일 `d2_entra > entr` 인지 |
| `d2_entra` 가 매수 미결제분을 차감하는가 | 매수 당일 `d2_entra < entr` 인지 |
| `aset_evlt_amt` 가 `entr` 기반인가 `d2_entra` 기반인가 | 두 값이 다른 날 항등식 재확인 |
| C vs C' (`d2_entra` vs `d2_pymn_alow_amt`) | 두 값이 갈리는 날 비교 |

이 측정은 조회 전용이며 **다음 체결이 있는 날 자동으로 가능**하다.
`phase1/account_equity_audit.py` 를 그대로 재실행하면 된다.
