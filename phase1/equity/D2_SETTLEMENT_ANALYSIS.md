# D2_SETTLEMENT_ANALYSIS

Iteration 7-2 · `account_snapshot`(150건) + `trades` 실측

## 1. 방법

`account_snapshot.deposit` 은 운영이 저장한 `withdrawable_cash`(=`pymn_alow_amt`) 다.
체결일 이후 deposit 이 **처음 변한 날**과 변화액을 찾고,
**체결금액과 부호·금액(±2%)이 모두 맞는 건만 "확정"** 으로 본다.
근접했다는 이유로 매칭하지 않는다.

⚠️ 한계: 스냅샷은 하루 1~수회(주로 08:50) 기록이라
"관측 N거래일 후" 는 **실제 결제 지연의 상한**이다. 정확한 T+N 은 확인 불가.

## 3. 결함 1 — 매도 후 equity 과소 (2026-05-22)

`account_snapshot` 원본:

```
2026-05-22 08:50   deposit 542,250   holding 4,490,750   total 5,033,000
2026-05-22 11:25   deposit 542,250   holding         0   total   542,250   ← 매도 4,526,860
2026-05-24 08:50   deposit 542,250   holding         0   total   542,250
2026-05-26 08:50   deposit 542,250   holding         0   total   542,250
2026-05-27 08:50   deposit 5,060,540 holding         0   total 5,060,540   ← 결제
```

포지션은 즉시 0 이 되는데 매도대금 4,526,860 은 3거래일 뒤에야 들어온다.
그 사이 총자산은 **542,250 으로 계산됐고**, 실제 자산은 약 5,060,540 이었다.

EC_HALT 는 이 기간 dd **-90.0%** 로 진입을 차단했다.
정상 값(5,060,540 / peak 8,543,116)이었다면 dd 는 -40.8% 다.
(둘 다 -18% 이하라 차단 자체는 바뀌지 않지만, 낙폭 수치는 2배 이상 틀렸다.)

## 4. 결함 2 — 매수 후 equity 과대 (2026-06-24)

```
2026-06-23 08:50   deposit 4,768,719  holding         0   total 4,768,719
              (장중 BUY 2,121,000)
2026-06-24 08:50   deposit 4,768,719  holding 1,860,000   total 6,628,719   ← 과대
2026-06-25 08:50   deposit 2,683,409  holding         0   total 2,683,409
```

매수대금 2,121,000 이 아직 차감되지 않은 채 매수한 주식의 평가액 1,860,000 이
더해져 총자산이 **약 2.09M 부풀려졌다**.

이 6,628,719 는 Iteration 7-1 에서 "왜 높았는지 확인 불가" 로 남겼던 값이다.
**원인이 확정됐다: 매수 미결제 이중계상.**

이 값이 그날 신고점으로 기록됐고, 이후 dd 를 전부 부풀렸다.

## 5. 결론

현재 계산식은 **결제 미완료 구간에서 양방향으로 틀린다.**

| 상황 | 현재 계산식 | 오차 방향 |
|---|---|---|
| 미결제 없음 | 정확 | 0 (2026-08-03 실측: 브로커 `aset_evlt_amt` 와 차이 0원) |
| 매도 직후 | 매도대금 누락 | **과소** |
| 매수 직후 | 매수대금 미차감 + 주식평가액 가산 | **과대** |

peak 은 과대 구간에서, dd 는 과소 구간에서 각각 최악값을 잡는다.
**두 오차가 EC_HALT 를 양쪽에서 악화시킨다.**
