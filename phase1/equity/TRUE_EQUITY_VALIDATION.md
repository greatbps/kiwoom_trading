## 1. 지시서 전제 변경 — 체결을 기다릴 수 없다

지시서는 "다음 매수/매도 체결 시 검증" 을 요구했다. 그런데:

```
최근 30일 체결          0건   (마지막 체결 2026-07-01)
최근 7일 EC_HALT     2,059건
보유 종목              0177R0 — 장기보유, 자동매매 분석/손절 제외
```

**EC_HALT 가 진입을 막고 있어 매수가 안 나가고, 유일한 보유 종목은
자동매매 제외 대상이라 매도도 안 나간다. 체결이 발생할 수 없다.**
EC_HALT 를 풀려면 Equity 를 고쳐야 하고, Equity 를 검증하려면 체결이 필요한
교착이다.

**대체 경로**: `ka01690`(일별잔고수익률)이 `qry_dt`(조회일자)를 받는다.
과거 결제 사건 당일의 **브로커 기준 총자산을 직접 조회**하면
기다리지 않고 같은 질문에 답할 수 있다.

## 4. KPI "Case C 오차 ≤ 0원" 에 대하여 — 정확히 0은 아니다

2일에서 +670원 / +3,990원(0.088%)이 남는다. 원인을 확인했다.

**이 잔차는 우리 계산식의 오차가 아니라 브로커 응답 내부의 차이다.**
`dbst_bal` 과 `tot_evlt_amt` 와 `day_stk_asst` 는 **같은 ka01690 응답**에서
나온 값인데, 브로커 자신의 `day_stk_asst` 가
`dbst_bal + tot_evlt_amt` 와 670원 / 3,990원 다르다.
`day_stk_asst` 가 무엇을 더 빼는지는 **확인 불가**.

예수금 항만 보면 8일 전부 정확히 일치한다.
→ KPI 의 취지(예수금 항의 정의가 맞는가)는 충족. 문자 그대로의 "0원" 은 미달.
