## 3. False Trigger 는 애초에 거의 없었다 — 7-1 §4 정정

Iteration 7-1 은 "임계값을 −30% 로 완화해도 17/29일 차단, 12일은 해제" 라고 썼다.
그 재구성은 **EC_HALT 가 실제로 기록된 날의 equity 표본만** 써서 peak 을 만들었고,
그래서 peak 이 실제보다 낮았다(하한). 당시 그 한계를 명시했지만
"12일 해제 가능" 이라는 수치는 결과적으로 과대였다.

브로커 전체 시계열(67일)로 다시 계산하면 실제 peak 은 **8,344,826**(2026-05-08)이고,
**2026-05-13 이후 어떤 날도 dd 가 −18% 위로 올라온 적이 없다.**

→ EC_HALT 는 오작동한 적이 없다. 계산 결함(Iteration 7-1/7-2)은 실재했지만,
   그 결함을 고쳐도 차단 판정 자체는 바뀌지 않는다.

## 4. 그래서 진짜 원인은 무엇인가

`equity` 가 **매매 성과 곡선이 아니라 원화 계좌 잔고 곡선**이라는 점이다.

```
2026-05-06  이체입금 +7,039,648   → peak 8,344,826 을 만듦 (peak 의 84%)
2026-05-13  원화→외화 -2,915,060  → 하루 만에 -39.4% 낙폭으로 기록됨
```

**입금하면 peak 이 오르고, 환전하면 낙폭이 된다.**
2026-05-13 의 환전 한 건이 그 뒤 3개월치 EC_HALT 를 켜 놓은 시작점이다.

TWR 로 외부 현금흐름을 제거하면 현재 낙폭은 −30.7% 다.
여전히 −18% 아래다 — **매매로도 실제로 30% 잃었다.**
(Iteration 4 의 "swing 5건이 실거래 손실의 95.2%" 와 일치한다.)

## 5. 재생 방법

```
입력  ka01690 qry_dt 일별 조회 67일        → TRUE equity (day_stk_asst)
      kt00015 위탁종합거래내역 39건        → 외부 현금흐름 6건, 미분류 0건
정책  eod_only_peak=True · peak 단조증가   → 운영 EquityController 와 동일
```

⚠️ 한계: 운영 EC_HALT 는 **장중** equity 로 판정하는데 이 재생은 **EOD** 값을 쓴다.
장중 변동으로 하루 안에서 −18% 를 오간 날은 재현되지 않는다.
단, 재생된 dd 가 −24% ~ −60% 구간이라 이 한계가 결론을 뒤집지는 않는다.
