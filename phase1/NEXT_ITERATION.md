## 3. 병목 분석 (정량)

### 3-1. 목표 KPI 가 서로를 밀어낸다

후보 프로파일 3종 × 필터 조합 16종 = **48개 조합 전수 평가**.

```
거래>=100 AND PF>=2.0 인 점 :  0개
4개 목표 전부 만족하는 점    :  0개
거래수 ↔ PF Spearman 상관   : -0.201
```

- 거래 ≥100 인 조합 중 최고 PF: **1.908** (G+D, MDD −14.20% 로 별도 탈락)
- PF ≥2.0 인 조합 중 최다 거래: **16건** (OPS+C)

목표까지의 간극은 조정 수준이 아니라 **6.25배**(16 → 100)다.

### 3-2. 왜 필터로는 안 되는가

필터는 후보를 줄이는 장치다. 거래를 100건으로 만들려면 후보를 늘려야
하는데, Phase 0.2 가 이미 후보 확대 → PF 하락을 보였다(117건 PF 1.813 →
260건 PF 1.589). 두 요구가 구조적으로 상충한다.

### 3-3. 승률이 유일한 지렛대다 — 그런데 진입 피처에 정보가 없다

Baseline 분해:

```
WR 43.2%   평균이익 +11.59%   평균손실 -4.86%   손익비 R = 2.385
검산 PF = R × WR/(1-WR) = 1.814   (실측 1.813 — 일치)
```

PF 2.0 에 도달하는 경로는 둘뿐이다.

| 경로 | 필요 개선 | Phase 1 에서 가능한가 |
|---|---|---|
| ① 승률 | 43.2% → 45.6% (+2.4pp) | 진입 측 — 가능 |
| ② 손익비 | 2.385 → 2.630 (+10.3%) | **청산 측 — 동결** |

WR 50% 를 달성하면 PF 는 자동으로 2.385 가 되어 PF 목표까지 충족된다.
즉 **승률이 진짜 목표**이고 필요 개선폭은 **+6.8pp** 다.

그런데 Experiment 3 이 측정한 결과, 진입 시점 피처는 이후 수익률에
대한 정보를 담고 있지 않다.

- 스코어 분해능 문제는 **해결됐다** (고유값 81개, 표준편차 12.89).
  Phase 0.1 의 "정수 3값" 문제는 사라졌다.
- 그럼에도 rho = −0.169 (p=0.131). 방향조차 음수다.
- **trend 축은 rho −0.267 (p=0.016) 으로 유의하게 음수**다.
  추세가 강할 때 진입할수록 성과가 나쁘다 — 평균회귀 신호다.
- 5분위가 단조가 아니다: Q2 승률 68.8% / Q3 18.8% / Q5 37.5%.

**결론: 진입 시점 정보만으로는 승률을 올릴 수 없다.** 필터를 더
설계해도 같은 결과가 나온다. 이건 필터 선택의 문제가 아니라 피처에
정보가 없다는 측정 결과다.

### 3-4. C(RVOL 상승)를 채택하면 안 되는 이유

성능 지표는 목표를 넘지만 표본이 없다.

```
전체 16건   Train 2건   Validation 9건   Test 3건
```

지시서 §10 "최소 30개 이상 거래 필요" 를 못 넘는다. Train 2건으로 낸
PF 2.509 는 숫자가 아니다.

## 4. 수정 대상 (Iteration 2)

Iteration 1 의 측정에 따르면 **Phase 1 의 범위 안에는 남은 지렛대가
없다.** 따라서 Iteration 2 는 두 갈래 중 하나를 골라야 하며, 이는
사용자 결정 사항이다.

### 안 A — 목표 KPI 재조정 (권장)

측정된 Pareto Frontier 에 맞춰 목표를 현실화한다.

| 항목 | 현재 목표 | 제안 | 근거 |
|---|---|---|---|
| PF | ≥2.0 | ≥1.85 | 거래 100건 이상 구간 최고 PF 1.908 |
| Win Rate | ≥50% | ≥45% | 피처에 예측력 없음이 측정됨 |
| Trades | ≥100 | ≥75 | OPS 81건이 현실적 상한 |
| MDD | ≤10% | ≤12% | 후보 확대 시 노출 증가는 구조적 |

목표를 이렇게 두면 **B(VWAP20)** 가 후보가 된다 (PF 1.849 · WR 44.2% ·
거래 77 · Test PF 1.879 — Test 구간에서 Baseline 을 앞선다).

### 안 B — 동결 해제 후 청산(Exit) 최적화

손익비 R 을 2.385 → 2.630 (+10.3%) 올리면 승률 개선 없이 PF 2.0 에
도달한다. 다만 이는 지시서 §3 이 금지한 `exit_logic_optimized.py`
영역이며, 별도 승인이 필요하다.

**정량 근거**: 현재 청산 사유 분포에서 SL 38건(47%) · TP 26건(32%).
평균손실 −4.86% 가 SL 라인(−5%)에 붙어 있어, SL 폭 또는 트레일링
조정이 R 에 직접 작용한다.

### 안 C — 백테스트/실거래 괴리 우선 (Experiment 1 후속)

Iteration 0 이 남긴 미해결 사항. 백테스트 PF 1.813 vs 실거래 PF 0.102.
백테스트에서 PF 를 1.8 → 2.0 으로 올려도 실거래에 옮겨가지 않으면
의미가 없다. 실거래 청산 사유에 장중 시각(`09:00 HARD_STOP`,
`14:50 오버나이트 차단`)이 찍혀 있어 두 시스템이 **다른 전략**을
돌리고 있음이 확인된다.

## 9. 남은 전제 (모든 안에 공통)

- Train 구간도 out-of-sample 이 아니다. Phase 0 에서 후보 조건을 고를 때
  이미 전 구간을 봤다.
- VWAP 은 20일 일봉 근사다. 운영 장중 VWAP 과 다른 지표다.
- Regime 은 유니버스 동일가중 지수 근사다. `core/regime_detector.py` 를
  쓰지 않았다.
- 청산은 일봉 스윙 근사다. 실거래 PF 와 직접 비교할 수 없다.
- yfinance 데이터 변동성이 실제보다 크다 (삼성전자 연율 56%).
